# kanban-agent

AI한테 일 맡기면 결국 내가 다 관리하게 되는 문제, 아시죠?

---

## 왜 만들었냐면

Claude Code로 큰 작업을 하다 보면 어느 순간 내가 PM이 되어 있습니다. "아까 그 결정 기억해?" "이 파일이랑 저 파일 연결되어 있는 거 알지?" "방금 만든 거랑 충돌 안 나?" 전부 내가 붙잡고 있어야 합니다.

`kanban-agent`는 그 짐을 에이전트들이 나눠 가지게 합니다.

프로젝트 루트에 SQLite 데이터베이스 하나가 생기고, 거기에 칸반 보드가 만들어집니다. 플래너, 구현자, 리뷰어, QA, 감독자 — 다섯 역할의 에이전트가 그 보드를 공유하며 일합니다. 누가 뭘 하는지, 어디까지 왔는지, 뭐가 막혔는지를 전부 DB가 기록합니다. 당신 머릿속이 아니라.

---

## 설치

```
/plugin install kanban-agent@skystarry-plugins
```

프로젝트에서 보드 초기화:

```
/kanban-agent:init
```

현황 확인:

```
/kanban-agent:status
```

## 다섯 역할

### `@kanban-planner`

코드 한 줄 쓰기 전에 먼저 생각합니다. 프로젝트를 훑고, 해야 할 일을 각자 독립적으로 진행할 수 있는 단위로 쪼갭니다. 작업이 너무 크거나 의존성이 꼬여 있으면 구현자가 중간에 막힙니다. 플래너는 그걸 미리 막는 역할입니다.

또 감독자가 "이 패턴으로 계속 실패하고 있어요"라고 남긴 조언을 읽고, 계획에 반영할지 말지 판단합니다.

### `@kanban-implementer`

작업 하나를 가져가서 자기만의 격리된 브랜치에서 코드를 짭니다. 린트, 빌드 통과하면 리뷰어한테 넘깁니다. 다른 구현자의 작업엔 절대 손대지 않습니다.

동시에 여러 개를 띄울 수 있고, 서로 충돌 없이 각자 작업합니다. 독립적인 작업이 여러 개 쌓여 있다면, 구현자 여러 개를 동시에 돌리면 됩니다.

### `@kanban-reviewer`

구현자가 만든 코드 변경사항을 읽습니다. 잘 됐으면 QA로, 아니면 "이 부분 때문에 안 됩니다"라는 메모와 함께 구현자한테 돌려보냅니다.

### `@kanban-qa`

소스 코드는 읽지 않습니다. 그냥 실행합니다. 앱을 켜서 실제로 동작하는지 확인하고, 필요하면 스크린샷도 찍습니다. `done`으로 옮길 수 있는 유일한 에이전트입니다. QA가 통과시키지 않으면 끝난 게 아닙니다.

### `@kanban-overseer`

보드 전체를 봅니다. 한 에이전트가 같은 작업에서 세 번째 실패 중이라면, 그건 그 에이전트 문제가 아니라 작업 정의나 아키텍처 문제일 수 있습니다. 감독자는 그런 패턴을 찾아내서 플래너한테 조언을 남깁니다. 코드를 짜거나 작업을 옮기진 않습니다. 진단만 합니다.

## 작업 흐름

```
draft → in_progress → review → qa → done
                    ↘ error ↗      ↘ error
                    need_verify     need_verify
```

단계를 건너뛸 수 없습니다. 리뷰나 QA에서 문제가 나오면 뒤로 돌아갑니다. 사람 판단이 필요한 상황은 `need_verify`에서 기다립니다.

## 권장 흐름

```
# 칸반 보드 최초 세팅
/kanban-agent:init

# 새 세션 시작 시 — DB 구조와 규칙을 컨텍스트에 로드
/kanban-core

# 에이전트 개별 실행
@kanban-planner             # 이번 마일스톤 계획 잡아줘

@kanban-implementer         # 구현 시작
@kanban-implementer         # 독립적인 작업이 여러 개면 동시에 실행
@kanban-implementer         # Ctrl+B로 백그라운드화 (tmux는 Ctrl+B 두 번)

@kanban-reviewer            # 코드 리뷰

@kanban-qa                  # 실행해서 확인

@kanban-overseer            # 뭔가 계속 막히면 전체 진단
```

실행 중인 에이전트는 `Ctrl+B`로 백그라운드로 보내고 다음 작업을 바로 시작할 수 있습니다. `/tasks`로 백그라운드 에이전트 목록과 상태를 확인하세요.
